# Working strategy

## Environments
- Google Cloud project `baitcheck`: the one real users depend on. Its OAuth
  consent screen, Marketplace deployment, Vertex and Web Risk quotas are the
  production ones.
- Google Cloud project `baitcheck-dev`: new builds and experiments. Own consent
  screen (Internal), own keys and quotas, linked to a dev copy of the Apps
  Script project. Breaking it costs nothing.
- The Apps Script side mirrors this: one script project per Cloud project.
  Push code with clasp to dev first; promote to prod by pushing the same
  tagged commit.

## Immutable versions
Apps Script already works this way: every deployment points at a numbered
script version, and a version's code can never change after it is created.
Promotion means creating a new version from a tagged commit and pointing the
deployment at it; rollback means pointing it back. Marketplace listings
reference the deployment, so users move with it. Tag the git commit with the
same number (`v1.2.0` ↔ Apps Script version 12, recorded in the release notes)
so code and deployment are traceable both ways. The dashboard repo uses
GitHub's immutable releases in the same spirit.

## Switching computers
Git is the transfer. Nothing is generated by hand:
1. Before leaving a machine: commit everything (or `git stash` for
   half-finished work), then `git push`.
2. On the other machine: `git pull`. The agent notes (`CLAUDE.md`), decisions,
   research and to-do lists are in the repo, so any agent session on any
   machine starts with the same context.
3. Local-only files never travel and never should: `.clasp.json`,
   `.clasprc.json`, `.env`, and the assistant's per-machine memory.
4. `docs/STATUS.md` is the short "where we are" note. Ask the agent to update
   it at the end of a session before switching; it is the one file meant to
   be rewritten every time.

## Secrets
Never in the repo, even encrypted for now. Apps Script secrets go in Script
Properties; dashboard secrets in its environment; shared credentials in the
company password manager.
